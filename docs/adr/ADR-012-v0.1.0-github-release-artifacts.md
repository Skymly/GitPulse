# ADR-012: v0.1.0 经 GitHub Releases 分发（签名 APK + Win zip）

| 字段 | 值 |
|------|-----|
| **状态** | Accepted |
| **日期** | 2026-07-27 |
| **关联 Issue** | [#54](https://github.com/Skymly/GitPulse/issues/54) |

## 背景

M0–M11 功能已落地。M12 为发版工程里程碑。既有文案笼统写「签名 / AAB」，且 CI 已在 `v*` tag 上发布未签名 Windows unpackaged exe；需钉死 v0.1.0 的分发渠道、产物形态与非目标，避免做成商店上架或新功能里程碑。

## 决策

- **M12 主目标**：发版工程。功能以 M0–M11 为准冻结；不做新功能 / 一等公民 UX 精修。
- **分发渠道**：仅 **GitHub Releases**（打 `v*` tag 触发）。不上 Microsoft Store / Google Play。
- **Release Artifact**：
  - Windows：self-contained publish **目录 zip**（修复「只挂 exe 可能缺依赖」）。
  - Android：**CI 签名 APK**（keystore 等经 GitHub Secrets）；**不做** AAB。
- **签名范围**：仅 Android 签名；Windows **不做** Authenticode（接受 SmartScreen 警告）。
- **交付拆分**：先合「发布流水线」；再单独 cut `v0.1.0`（仍属 M12）。不强制流水线票内打 tag。
- **cut 门槛**：短冒烟——Win 运行 + PAT；Android 侧载 APK + PAT；各点开一等公民一页不崩。版本说明以 `CHANGELOG.md` 将 `[Unreleased]` 收成 `[0.1.0]` 为准。
- **明确不做（v0.1.0）**：商店上架、Win 码签、AAB、GitHub App OAuth、Android 出应用通知、iOS / MacCatalyst、新功能 / Diff 等精修。

## 后果

- **正面**：与个人项目首发匹配；复用现有 tag → Nuke `Release` 骨架；APK 侧载友好。
- **正面**：流水线与首次公开发版解耦，符合「不主动发版」习惯。
- **负面**：用户须从 GitHub 下载；Win 可能遇 SmartScreen；日后上架需另开里程碑并可能另签 Play 密钥策略。
- **文档**：ROADMAP / DEVELOPMENT / CONTEXT 中「AAB」用语收敛为可安装签名包 / Release Artifact；商店 AAB 延后。
